# 开发路线图

目标是在有限比赛时间内交付可演示闭环：上传教材、解析章节、生成知识图谱、跨教材整合、带引用 RAG、教师反馈和报告。

## 总体策略

优先完成 P0 的端到端链路。每个阶段都保留 mock/fallback，避免 LLM、embedding 或大 PDF 处理不稳定时导致演示中断。所有医学结论必须能追溯到教材原文，证据不足时明确返回“当前知识库中未找到相关信息”。

## 0:00-0:30 阶段 1：骨架与上传

交付物：

- FastAPI + React/Vite/TypeScript 项目结构。
- `.env.example`、`requirements.txt`、`package.json`。
- 上传界面和 mock 上传接口。
- Git 忽略规则，确保教材 PDF 与缓存不入库。

验收点：

- `GET /api/health` 正常。
- 前端能打开三栏界面。
- 上传 PDF/MD/TXT 后能显示文件名、格式、大小、状态。

## 0:30-1:30 阶段 2：教材解析

后端重点：

- 新增解析服务，输出 textbook、chapter、page、char_count。
- PDF 使用 PyMuPDF 逐页解析，避免一次性加载整本书。
- Markdown/TXT 使用标准库解析。
- 章节识别先用正则覆盖“第 X 章”，后续再扩展字体特征。
- 将解析结果缓存到 `data/processed/`。

前端重点：

- 上传后轮询或刷新解析状态。
- 展示总页数、总字数、章节数量。

风险控制：

- 若 PDF 章节识别失败，至少按页或固定窗口生成默认章节，保证后续图谱/RAG 可运行。

## 1:30-2:20 阶段 3：知识图谱

后端重点：

- 定义知识节点、关系边 schema。
- 每章提取 3-8 个知识点，先支持 mock fallback。
- LLM prompt 强制输出 JSON、章节、页码、source_text。
- 图谱构建接口输出 nodes 和 edges。

前端重点：

- 接入图谱库，渲染节点和关系。
- 点击节点显示定义、章节、页码和原文片段。
- 不同教材来源使用不同颜色，频次用节点大小表示。

风险控制：

- LLM 不可用时，用章节标题和关键词规则生成少量节点，保证可视化不断链。

## 2:20-3:10 阶段 4：跨教材整合

后端重点：

- 对知识点名称、定义、source_text 生成 embedding。
- 相似度召回候选，再用阈值或 LLM 判断同义/近义。
- 生成 `merge`、`keep`、`remove` 决策。
- 计算压缩比，目标不超过 30%。

前端重点：

- 展示整合决策列表、原因、置信度和可编辑状态。
- 展示压缩统计。

风险控制：

- 先用规则相似度或简化 embedding fallback，后续再接正式模型。

## 3:10-3:50 阶段 5：RAG 问答

后端重点：

- 500-800 字 chunk，50-100 字 overlap。
- chunk 保留 textbook、chapter、page_start、page_end。
- 检索 top-5，生成带引用回答。
- 上下文不足时固定兜底。

前端重点：

- 展示索引状态。
- 输入问题后展示回答、引用列表和原文 chunk。

风险控制：

- 若 LLM 不可用，返回 top chunk 摘要式答案和引用，保持“有据可查”。

## 3:50-4:20 阶段 6：教师反馈

后端重点：

- 保存会话内对话历史。
- 支持解释指定整合决策。
- 支持自然语言触发保留、拆分、合并至少一种修改。

前端重点：

- 对话 Tab 展示历史。
- 修改后刷新决策列表或图谱状态。

风险控制：

- 先实现规则解析：“保留 X”“拆分 X 和 Y”“合并 X 和 Y”。

## 4:20-4:45 阶段 7：文档与报告

必须完成：

- `README.md`：环境依赖、安装、配置、启动、使用说明。
- `docs/需求分析.md`：粒度、重复判定、压缩比、RAG 分块依据。
- `docs/系统设计.md`：架构、数据流、技术选型、API。
- `docs/Agent 架构说明.md`：模块职责、数据流、取舍、局限、创新点。
- `report/整合报告.md`：系统真实统计、典型决策、教学完整性说明。

写作原则：

- 数据必须来自系统真实输出。
- 没有完成的 P1/P2 不写成已完成能力。

## 4:45-5:00 最终演示与提交

演示顺序：

1. 打开 Web 页面，展示上传区、图谱区、右侧 Tab。
2. 上传 1-2 本教材并展示解析状态。
3. 构建图谱，点击节点查看出处。
4. 运行跨教材整合，展示决策和压缩比。
5. 提问 RAG，展示回答和引用。
6. 用教师对话修改一项决策。
7. 打开报告和 README，说明可复现方式。

提交检查：

- `git status --ignored` 确认 PDF、`textbooks/`、`data/`、`.env`、`node_modules/`、`dist/` 均未提交。
- 前后端本地启动命令可复现。
- 最后一次提交已推送到 GitHub。
